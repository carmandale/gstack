gstack at a glance

A software factory made of agent roles, generated skills, browser tools, and memory.

gstack packages opinionated development workflows as slash-command skills. The skills help an AI agent plan like a product team, review like a senior engineer, test with a real browser, ship with release discipline, and keep useful project knowledge alive between sessions.

Workflow roles Planning, design, engineering, QA, security, release, documentation, and operations are split into focused skills.
Runtime tools A persistent Chromium daemon, design helpers, PDF/docs tooling, and deploy helpers turn prompts into executable work.
GBrain included The repo explicitly includes /setup-gbrain and /sync-gbrain, so the memory loop appears in the diagram.

How the pieces fit

Read top to bottom: user intent enters through slash commands, skills call runtime tools, generated docs keep host installs current, and GBrain feeds durable context back into future sessions.

The stack in five layers

The important design choice: most of gstack is Markdown methodology, but the risky loops have real tooling behind them.

1. Skills

Specialist roles

Slash commands such as /office-hours, /review, /qa, and /ship give the agent a narrower job and a stronger checklist.

2. Templates

Generated docs

SKILL.md.tmpl files hold the human workflow. gen-skill-docs.ts fills command references and host-specific blocks.

3. Browser

Real UI contact

The browse binary talks to a long-lived Chromium daemon, so QA can click, type, inspect console output, and keep session state.

4. Memory

GBrain loop

/setup-gbrain connects a memory backend. /sync-gbrain indexes repo code and writes search guidance for future agents.

5. Checks

Freshness gates

bun test, bun run build, and bun run skill:check keep generated skills and runtime references from drifting.

A simple try-out path

This is the low-risk path for understanding what gstack feels like before wiring the whole suite into a global setup.

1. Start with a role Use /office-hours or /plan-ceo-review to feel the product-shaping side without touching runtime state.
2. Add browser contact Try /browse or /qa against a safe local or staging page to see the persistent Chromium loop.
3. Keep it current Run the generated-doc checks before trusting host output, especially after changing templates or browser commands.
4. Opt into memory Use /setup-gbrain only when you want durable cross-session knowledge, then /sync-gbrain per repo.

GBrain is not inferred here. It is named in the repo's skill list and README, and the architecture docs include GBrain resolver placeholders that inject context-load and save instructions into brain-aware skills.
